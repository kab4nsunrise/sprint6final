## Описание финального задания: Конвертер азбуки Морзе

В этом проекте реализуется веб-сервис для преобразования текста в код Морзе и обратно. Пользователь загружает файл через HTML-форму, сервер автоматически определяет, что содержится в файле (обычный текст или код Морзе), выполняет соответствующее преобразование и возвращает результат, а также сохраняет его в локальный файл. Проект демонстрирует навыки создания HTTP-сервера, работы с формами, загрузки файлов, определения типа данных и использования внешних пакетов.


## Архитектура проекта

Проект состоит из трёх основных пакетов (`service`, `handlers`, `server`) и главного пакета `main`. Также используется вспомогательный пакет `morse` (находится в `pkg/morse`), предоставляющий готовые функции для конвертации между текстом и кодом Морзе (поддерживается русский алфавит).


### Пакет `service` – автоопределение и конвертация

Этот пакет содержит единственную экспортируемую функцию, которая принимает строку (содержимое файла) и возвращает преобразованную строку, а также ошибку.

**Задача функции:**  
- Проанализировать входную строку и определить, является ли она кодом Морзе или обычным текстом.  
- Если это текст – преобразовать его в код Морзе с помощью `morse.ToMorse()`.  
- Если это код Морзе – преобразовать его в текст с помощью `morse.ToText()`.  
- Вернуть результат и `nil` при успехе, либо ошибку при невозможности определения или конвертации.

**Критерии определения:**  
Для различения используется пакет `strings`. Проверяется наличие характерных для кода Морзе символов (точки, тире, пробелы, разделители). Например, если строка содержит только символы `.`, `-`, пробелы и слэши – скорее всего, это код Морзе. Иначе – текст. Также учитываются возможные краевые случаи (пустая строка, смешанные данные). В случае неоднозначности или ошибки функция возвращает ошибку.


### Пакет `handlers` – обработчики HTTP-запросов

Пакет содержит две функции-обработчика (хендлера), которые регистрируются в маршрутизаторе.

#### 1. Хендлер для корневого эндпоинта `/`

- Отдаёт клиенту HTML-страницу из файла `index.html`, расположенного в корне проекта.  
- Используется для отображения формы загрузки файлов.

#### 2. Хендлер для эндпоинта `/upload`

Обрабатывает POST-запросы, отправленные из формы. Последовательность действий:

- **Парсинг формы** – извлекает загруженный файл из поля формы (используется `r.ParseMultipartForm` и `r.FormFile`).  
- **Чтение файла** – считывает содержимое в строку.  
- **Закрытие файла** – обязательно закрывает дескриптор после чтения.  
- **Вызов функции автоопределения** – передаёт прочитанную строку в функцию из пакета `service` и получает преобразованный результат.  
- **Сохранение результата** – создаёт новый локальный файл с уникальным именем (генерируется на основе текущего времени UTC и оригинального расширения исходного файла, определяемого через `filepath.Ext()`). Записывает в него преобразованную строку.  
- **Возврат ответа** – возвращает клиенту преобразованный текст (например, в виде простого текстового ответа или JSON).  

При возникновении любой ошибки на любом этапе хендлер возвращает HTTP-статус `500 Internal Server Error` и сообщение об ошибке.


### Пакет `server` – создание и настройка HTTP-сервера

Этот пакет предоставляет функцию, которая инициализирует и возвращает готовый к запуску экземпляр HTTP-сервера с предварительно настроенным роутером и логгером.

**Структура сервера** содержит два поля:
- `Logger *log.Logger` – для логирования ошибок и событий.  
- `HTTPServer *http.Server` – сам HTTP-сервер.

**Функция создания** принимает логгер и выполняет следующие шаги:
1. Создаёт новый маршрутизатор (`http.ServeMux`).  
2. Регистрирует хендлеры для эндпоинтов `/` и `/upload` (из пакета `handlers`).  
3. Создаёт экземпляр `http.Server` со следующими настройками:
   - `Addr = ":8080"` – порт прослушивания.  
   - `Handler = роутер` – все запросы обрабатываются зарегистрированными хендлерами.  
   - `ErrorLog = логгер` – все ошибки сервера пишутся в лог.  
   - `ReadTimeout = 5 * time.Second` – максимальное время на чтение запроса.  
   - `WriteTimeout = 10 * time.Second` – максимальное время на запись ответа.  
   - `IdleTimeout = 15 * time.Second` – максимальное время ожидания следующего запроса в keep-alive.  
4. Возвращает указатель на созданную структуру (или сразу на `http.Server` – по выбору разработчика).


### Пакет `main` – точка входа

В функции `main()` выполняются следующие действия:

- Создаётся логгер (например, с использованием `log.New()` с выводом в `os.Stdout` или `os.Stderr`).  
- Вызывается функция из пакета `server` для получения настроенного сервера.  
- Запускается сервер методом `ListenAndServe()`.  
- Если при запуске возникает ошибка, она логируется на уровне `Fatal` (принудительное завершение программы с записью в лог).


## Взаимодействие компонентов

1. Пользователь открывает в браузере `http://localhost:8080/`.  
2. Сервер отдаёт `index.html` с формой выбора файла.  
3. Пользователь выбирает файл (например, `test.txt` с обычным текстом или `test12.txt` с кодом Морзе) и отправляет форму.  
4. Запрос направляется на `/upload`.  
5. Хендлер читает файл, передаёт содержимое в `service.AutoDetectAndConvert()`.  
6. Функция из `service` определяет тип и вызывает соответствующую функцию из пакета `morse`.  
7. Преобразованный результат возвращается в хендлер.  
8. Хендлер сохраняет результат в новый файл (имя генерируется на основе времени и расширения оригинала) и возвращает преобразованную строку в ответе.  
9. Пользователь видит результат преобразования.


## Используемые технологии и пакеты

- **Стандартная библиотека Go**: `net/http`, `html/template`, `strings`, `path/filepath`, `time`, `log`.  
- **Вспомогательный пакет `morse`** – предоставляет функции `ToText` и `ToMorse` для работы с русским алфавитом.  
- **Обработка ошибок** – все критические ошибки логируются и возвращаются клиенту с кодом 500.


## Особенности реализации

- **Автоопределение** основано на эвристическом анализе строки с помощью `strings.ContainsAny` и других проверок, чтобы различать текст и код Морзе.  
- **Сохранение результата** – пример учебного задания: создание постоянных файлов небезопасно в реальных проектах, но здесь используется для наглядности. Имена файлов генерируются так, чтобы избежать конфликтов.  
- **Таймауты** сервера настроены для предотвращения зависаний и атак типа медленного чтения.  
- **Логирование** используется на всех этапах – от ошибок парсинга формы до проблем с записью файла.

## Итог

Данный проект является полноценным веб-приложением на Go, демонстрирующим навыки работы с HTTP, обработкой форм, файловым вводом-выводом, и применением сторонних пакетов. Результат – простой и удобный онлайн-конвертер азбуки Морзе, готовый к запуску и использованию.
